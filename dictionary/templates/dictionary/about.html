About the Project

Garuda Dictionary

A thoughtful Hindi–English dictionary experience built as a demonstration project for the Garuda Prakashan × Rishihood University Live Project Assignment.

⚠️
Demonstration Project Notice

This is a student demonstration project. The dictionary currently contains {{ total_count }} illustrative entries that have not been verified by Garuda Prakashan's editorial team. This application is not an official Garuda Prakashan product. All example sentences, etymologies, and definitions are based on common usage and standard references, and should be reviewed by qualified linguists before any official use.

Project Overview

Garuda Dictionary is a full-stack web application built with Django (Python) and vanilla JavaScript. It demonstrates a usable, well-designed Hindi–English dictionary with multi-script search support — a genuine product challenge, not a tutorial exercise.

The application was designed to serve users who think in Hindi but may type in English, use Romanised transliterations with varying spellings, or who may know an English concept and want to find the Hindi word.

Problem Statement

Hindi speakers frequently encounter friction when searching for dictionary entries online. Common problems include:

  • No single accepted Romanisation of Hindi words (dharma vs dharm vs dharama)
  • Dictionary apps that require Devanagari input exclusively
  • Poor handling of diacritical marks and Unicode normalisation
  • Lack of alternate spelling matching
  • Minimal Devanagari font support in dictionary UIs

Garuda Dictionary addresses each of these by supporting explicit alternate Romanisations per entry, NFC Unicode normalisation, case-insensitive search, and partial prefix matching.

Search Algorithm

Search operates in six ranked tiers:

  1. Exact Devanagari match — highest priority
  2. Exact Romanised match — case-insensitive
  3. Alternate Romanisation match — explicit comma-separated variants per entry
  4. Prefix match — Devanagari or Romanised prefix
  5. Partial match — substring in Devanagari, Romanised, or alternates
  6. English meaning match — keyword in meaning or definition

Results are sorted by rank then alphabetically. Unicode NFC normalisation is applied before matching to handle equivalent Devanagari representations.

Technology Stack

Backend: Python 3, Django, SQLite (via Django ORM)
Frontend: Django Templates (HTML5), CSS3 (custom design system), Vanilla JavaScript
No external JS frameworks — all interactions use browser-native APIs.

Design Decisions

Django was chosen because it provides a clean MVC architecture, built-in admin interface, and ORM — all without requiring a separate API layer for a server-rendered application. SQLite is sufficient for a demonstration dataset and requires zero configuration. Vanilla JavaScript was chosen to keep the code accessible to beginners and avoid build tooling complexity.

The design is inspired by Indian literary heritage — using warm ivory, saffron, and terracotta tones — while maintaining the clarity and usability standards of contemporary digital publishing. The Noto Serif Devanagari and Noto Sans Devanagari fonts from Google Fonts provide high-quality Devanagari rendering across all platforms.

Limitations

  • Dictionary contains ~{{ total_count }} illustrative entries only
  • No automatic Devanagari-to-Romanised transliteration (by design — this avoids inaccuracies)
  • No audio pronunciation
  • No user accounts or word bookmarking
  • No synonym/antonym relationships
  • Demonstration content is not editorially verified

Future Improvements

  • Integration of Garuda Prakashan's authorised, verified dictionary dataset
  • Audio pronunciation using recorded or synthesised audio
  • Full-text search using PostgreSQL or Elasticsearch for large datasets
  • User bookmarks and word-of-day notifications
  • Synonym and antonym cross-links
  • Multi-language support (Gujarati, Bengali, Tamil, etc.)
  • Progressive Web App (PWA) for offline access
